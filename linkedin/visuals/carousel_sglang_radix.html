Why Multi-Turn Agents Burn Compute

Why multi-turn LLM agents waste 70% of compute re-evaluating system prompts and how Radix Trees fix it.

The Bottleneck
In a 15-step agent loop, the system prompt, tool schemas, and prior trajectory steps are sent on every single turn. Standard serving engines discard or naively recompute KV cache states across branching tool calls.
70% of prefill FLOPs wasted re-reading static tool definitions

KV Cache as a Radix Tree

Architecture Shift

Architecture Shift
Instead of treating prompts as isolated requests, SGLang maintains a Least-Recently-Used (LRU) Radix Tree of token prefixes in GPU VRAM. Shared prefixes across subagents point to the exact same KV memory blocks.
RadixTree: [System Prompt] -> [Tool Schemas] -> [Branch A / Branch B]

VRAM Eviction & Cache Thrashing

The Engineering Catch

The Engineering Catch
Radix trees only help if your prompts share deterministic prefixes. If you inject dynamic timestamps or random UUIDs at the top of your system prompt, you invalidate the entire prefix tree on line 1.
Rule: Always put static system prompts & tools first; dynamic state last
